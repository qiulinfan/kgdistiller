# Sheet contract

A sheet is the generated def/pending view of one registered source. kgd writes
it; agents never hand-write or edit it.

- Path: `<base root>/.knowledge/sheets/<source path>.md`, for example
  `.knowledge/sheets/notes/math/linear-algebra/chapters/01-review.tex.md`.
- Written by `kgd sheet SOURCE` through a temp file and an atomic replace,
  creating parent folders.
- The only state read back is the checkbox of each row under `## Drafts`.
  Regeneration keeps the ticks of rows whose draft still exists and overwrites
  everything else, so annotations belong in drafts or records, never in sheets.
- A checkbox means "selected for acceptance", never "understood".
- `kgd index` never writes sheets.

## Inventory: `kgd sheet SOURCE --json`

Prints the extraction profile and inventory of the source and writes nothing:

```json
{"base": "notes", "source": "notes/math/…/01-review.tex", "type": "math-notes",
 "node_kinds": ["definition", "theorem"],
 "relation_kinds": {"implies": ["premise", "conclusion"]},
 "epistemic": ["proved", "stated"], "guidance": "…", "line_count": 77,
 "records": [{"uid": "notes:subspace", "label": "Subspace", "kind": "definition",
              "class": "node", "lines": "7-19", "understanding": "understood", "gloss": "…"}],
 "drafts": [{"id": "direct-sum-criterion", "label": "…", "kind": "implies",
             "class": "relation", "lines": "37-41"}],
 "pending": [{"term": "vector space", "owners": [{"uid": "notes:subspace", "role": "requires"}]}]}
```

`records` are the accepted records whose `source` is this file, `drafts` the
drafts citing it, and `pending` every term value of those accepted records,
grouped by name key. Read the source text itself with your own tools; the
inventory carries no lines. An unregistered file is an error that asks for a
glob in `$KGDISTILLER_HOME/config.json`; report it instead of registering one.

## Generated sheet

```markdown
<!-- generated by kgd sheet; only draft checkboxes are read back -->
# notes/math/linear-algebra/chapters/01-review.tex

[[notes/math/linear-algebra/chapters/01-review.tex]] · type math-notes · 7 accepted · 2 drafts

## definition
- [[.knowledge/entries/subspace|Subspace]] · L7-19 · understood — vector space $V$ 的 subset …
- [[.knowledge/entries/direct-sum|Direct sum]] · L37-41 — 若 …

## implies
- [[.knowledge/entries/sum-of-two-subspaces-is-a-subspace|Sum of two subspaces is a subspace]] · L24-32 · premise: Subspace · conclusion: Sum of subspaces — 若 …

## Pending
- dimension — Dimension of a direct sum (uses)
- vector space — Subspace (requires)

## Drafts
- [x] [[.knowledge/drafts/direct-sum-refines-subspace-sum|Direct sum refines subspace sum]] · contrasts · L34-34 · subject: Direct sum · contrast: Sum of subspaces — …
- [ ] [[.knowledge/drafts/direct-sum-criterion|Direct sum criterion]] · implies · L37-41 · premise: Direct sum refines subspace sum · conclusion: Direct sum — …
```

Sections and rows:

- One `## <kind>` section per kind of accepted record: the type's node kinds
  first, then its relation kinds, each in the type's order, then `## other` for
  kinds the type does not declare. Rows are sorted by first line, then id.
- Row grammar:

  ```
  accepted: - [[.knowledge/entries/<id>|<label>]] · L<a>-<b>[ · <understanding≠unknown>][ · <role>: <v>, …]… — <gloss>
  draft:    - [ ] [[.knowledge/drafts/<id>|<label>]] · <kind> · L<a>-<b>[ · <role>: <v>, …]… — <gloss>
  ```

  `<v>` is the target record's label (its id or uid when the target is
  missing) or the pending term itself. In display text `|`, `[` and `]` become
  spaces. Links are vault-relative paths, so Obsidian resolves them exactly.
- `## Pending` lists each pending term of this source's accepted records once,
  with the labels and roles of the records that use it.
- `## Drafts` lists every draft whose `source` is this file, by line.

## Harvest

`kgd harvest SHEET [--dry-run]` reads the ticked rows under `## Drafts`
(`- [x] [[.knowledge/drafts/<id>|…]]`), skips rows whose draft no longer exists,
runs one `kgd accept` on the rest and, on success, regenerates the sheet. It
prints the accept result: `refused`, `would_create` or the receipt
`{created, understanding_set}`. A refusal changes nothing; the usual message is
`select [[x]] too`, meaning a ticked draft links an unticked draft.
